# Kent Repertory OCR Validation Guide

## Quick Validation Checklist

Use this guide to validate Kent Repertory Excel files **generated by the browser-based OCR Digitizer** before using them clinically. The OCR tool uses Tesseract + AI (Groq/OpenAI) to automatically extract and structure rubrics from scanned pages.

**System Overview:**
- Upload: Scanned image/PDF → Browser
- OCR: Tesseract extracts raw text
- AI: Groq/OpenAI structures into Kent format with full hierarchy paths
- Output: Download Excel file directly (no database storage)
- Target Accuracy: 96%+ per page

---

## Pre-Import Validation (3-Step Process)

### Step 1: Visual Structure Check (30 seconds)

Open the Excel file and scan for these patterns:

**✅ Good Signs:**
- [ ] Rubric column shows hierarchical paths: `HEAD - PAIN - walking rapidly`
- [ ] Chapter column shows single words: `HEAD`, `MIND`, `ABDOMEN`
- [ ] Medicine column shows abbreviations: `bell`, `nux-v`, `calc`
- [ ] Grade column shows only numbers: `1`, `2`, `3`

**🚨 Red Flags:**
- [ ] Rubric shows only short phrases: `walking rapidly` (missing parent sections)
- [ ] Chapter shows full paths: `HEAD - PAIN - walking` (wrong column)
- [ ] Medicine shows full names: `Belladonna` (should be `bell`)
- [ ] Grade shows text: `high`, `moderate` (should be `1`, `2`, `3`)

---

### Step 2: Hierarchy Path Validation (5 minutes)

Pick 10 random rubrics and verify the **complete path** is present.

#### Validation Method:

1. **Open the source PDF** to the corresponding page
2. **Trace the indentation levels** in Kent's printed text
3. **Verify each level is in the Excel path**

#### Example from Page 158:

**PDF Visual Structure (indentation shows hierarchy):**
```
HEAD
  PAIN
    sudden
      swallowing, when
        distant
        others, of
        tea, from
    weather, from changes of
      cloudy
      cold
        damp, cold
```

**Excel Rubric Column MUST match:**
```
HEAD - PAIN - sudden - swallowing, when - distant
HEAD - PAIN - sudden - swallowing, when - others, of
HEAD - PAIN - sudden - swallowing, when - tea, from
HEAD - PAIN - weather, from changes of
HEAD - PAIN - weather, from changes of - cloudy
HEAD - PAIN - weather, from changes of - cold
HEAD - PAIN - weather, from changes of - damp, cold
```

**Common Error Pattern:**
```
❌ HEAD - weather, from changes of          Missing: "PAIN"
❌ HEAD - PAIN - cloudy                      Missing: "weather, from changes of"
❌ HEAD - cold                               Missing: "PAIN - weather, from changes of"
```

### Step 3: Medicine Abbreviation Check (3 minutes)

Scan the Medicine column for these **common OCR errors**:

#### High-Frequency Error Patterns:

| If you see | It should be | Medicine Name |
|-----------|--------------|---------------|
| `Aun-c` or `An-c` | `am-c` | Ammonium carbonicum |
| `nux-n` | `nux-v` | Nux vomica |
| `ant-t` | `ant-c` | Antimonium crudum |
| `clin` or `cinic` | `chin` | China officinalis |
| `carb-ani` | `carb-an` | Carbo animalis |
| `nuang` | `mang` | Manganum |
| `ziing` | `zing` | Zingiber |
| `bry.` (with period) | `bry` | Bryonia |
| `Bell` (capital B) | `bell` | Belladonna |

#### Quick Scan Method:
1. Sort Medicine column alphabetically
2. Scan for unusual spellings (like `Aun`, `clin`, `ziing`)
3. Cross-reference with Kent's medicine index
4. Fix before import

## Page-by-Page Validation Protocol

### For Each Page Extraction:

#### 1. Count Check
- [ ] Compare total rubric entries in Excel vs visual count in PDF
- [ ] Acceptable: 96%+ accuracy (4 missing per 100 is OK if they're deeply nested)
- [ ] Unacceptable: >5% missing or any major section missing

#### 2. Section Boundary Check
- [ ] Verify chapter transitions are correct (e.g., HEAD → EYE transition)
- [ ] Check for "phantom chapters" (common error: continuation headers misread as new chapters)
- [ ] Example: "swallowing, when:" is NOT a SWALLOWING chapter

#### 3. Continuation Column Check
When a page has **two columns** (left and right):
- [ ] Right column header is part of path, not new chapter
- [ ] Example: Right column starts with "swallowing, when:" — this continues `HEAD - PAIN - sudden - swallowing, when`

#### 4. Grade Validation
- [ ] All grades are integers: `1`, `2`, or `3`
- [ ] No decimals: `1.5` ❌
- [ ] No text: `high`, `moderate` ❌
- [ ] No zeros: `0` ❌

## Common Error Patterns by Page Section

### Pattern 1: Missing Intermediate Section
**Location:** End of major sections, modality sub-rubrics

**Example:**
```
❌ HEAD - talking, while, agg.
✅ HEAD - PAIN - sudden - talking, while, agg.
```

**How to Catch:**
- Sort rubrics alphabetically
- Look for sudden "jumps" in specificity
- If detail rubrics appear without their parent, parent is missing

### Pattern 2: Continuation Header Misread
**Location:** Page columns, section continuations

**Example:**
```
PDF shows:
  [Left column ends with:]
  PAIN, sudden
    swallowing, when

  [Right column header:]
  swallowing, when:    ← This is a continuation marker!
    distant
    others, of

❌ OCR creates wrong structure:
SWALLOWING                          ← Wrong chapter!
  distant
  others, of

✅ Correct structure:
HEAD - PAIN - sudden - swallowing, when - distant
HEAD - PAIN - sudden - swallowing, when - others, of
```

**How to Catch:**
- Check if new "chapter" is actually a lowercase rubric phrase
- Verify against Kent's index (e.g., "SWALLOWING" as standalone chapter doesn't exist on p156)

### Pattern 3: Complex Descriptive Rubrics Split
**Location:** Rubrics with long English descriptions

**Example:**
```
❌ Split incorrectly:
HEAD - PAIN - mist
HEAD - PAIN - before
HEAD - PAIN - eyes

✅ Should be one rubric:
HEAD - PAIN - mist before eyes
```

**How to Catch:**
- If consecutive rubrics are single words that form a phrase when combined
- Check if only one medicine is listed across these "split" entries
- Verify against PDF (is it one line or multiple?)

## Validation Testing Queries

### Query 1: Hierarchy Depth Check
**Purpose:** Find rubrics with suspiciously shallow paths

**Method:** Count dashes in Rubric column
```
Expected depth for detail rubrics: 3-5 levels (3-5 dashes)
Suspicious depth: 1-2 levels (1-2 dashes) for end-section rubrics
```

**Example:**
```
✅ Normal depth: HEAD - PAIN - sudden - talking, while, agg.  (4 levels)
⚠️  Suspicious:  HEAD - talking, while, agg.                 (2 levels) ← Missing "PAIN - sudden"
```

### Query 2: Medicine Name Pattern Check
**Purpose:** Find medicine names with unusual character patterns

**Red flags:**
- Names with 2+ capital letters: `AUn-c`, `BEll`
- Names with numbers: `nux-v2`, `calc3`
- Names >10 chars: `belladonn`, `calcareum` (should be abbreviated)
- Names with special chars: `bell.`, `nux_v`, `calc()`

### Query 3: Parent-Child Relationship Validation
**Purpose:** Verify all detail rubrics have their parent rubrics

**Method:**
1. Extract all rubrics with 3+ levels (e.g., `A - B - C - D`)
2. Check that parent exists (e.g., `A - B - C` must also be present)
3. If parent missing, flag for review

**Example:**
```
If Excel contains:
  HEAD - PAIN - sudden - swallowing, when - distant

Then it MUST also contain:
  HEAD - PAIN - sudden - swallowing, when
  HEAD - PAIN - sudden
  HEAD - PAIN
```

## Priority Levels for Corrections

### 🔴 Critical (Must Fix Before Import)
- Missing hierarchy levels (e.g., missing "PAIN" in path)
- Wrong chapter assignments
- Invalid grades (not 1, 2, or 3)

### 🟡 High (Should Fix Before Import)
- Medicine abbreviation errors
- Missing parent rubrics (orphaned detail rubrics)
- Cross-references treated as medicines

### 🟢 Low (Can Fix Later)
- Hindi translation typos
- Formatting inconsistencies (spacing, capitalization)
- Missing deeply nested sub-sub-rubrics (<4% total)

## Tips for OCR Operators

### Before Starting:
1. **Study Kent's structure** — understand his indentation system
2. **Review page samples** — see correct vs incorrect examples
3. **Check your tools** — ensure OCR engine is trained on medical text

### During Extraction:
1. **Follow indentation visually** — each indent level = one path segment
2. **Mark continuation headers** — note when columns continue previous section
3. **Flag ambiguous cases** — better to flag than guess

### After Extraction:
1. **Run spell-check** on medicine names against Kent's medicine index
2. **Visual scan** for "too short" paths (likely missing parents)
3. **Spot-check** random samples against PDF (10 rubrics per page)

### Quality Over Speed:
- **Target:** 95%+ accuracy on first pass
- **Reality:** Corrections take longer than careful initial extraction
- **Best Practice:** Validate as you go, not at the end

## For AI Extraction Issues

If the AI consistently fails to extract proper hierarchy paths:

### Check OCR Text Quality
The AI can only structure what Tesseract OCR provides. Poor OCR = poor AI extraction.

**Test:** Look at the raw OCR text (if accessible in logs):
```
Good OCR:
HEAD
  PAIN
    sudden
      swallowing, when: Bell., bry., nux-v.

Bad OCR:
HE AD
PAlN
sud den
swall owing when Bell bry nux v
```

### Improve Source Quality
1. **Scan at 300+ DPI** (current standard for medical texts)
2. **Good lighting** - avoid shadows, glare, or yellowed pages
3. **Straight alignment** - crooked scans confuse OCR
4. **High contrast** - black text on white background works best
5. **Clean lens** - smudges cause character misrecognition

### AI Model Selection
The system tries these models in order:
1. **OpenAI GPT-4o-mini** (primary) - Best hierarchy reasoning
2. **Groq Llama 3.3 70B** (fallback) - Fast, good quality
3. **Groq Llama 3.1 8B** (last resort) - Fast but lower quality
4. **Rule-based parser** (if all AI fails) - Deterministic but basic

If extractions are poor, check which model succeeded in the response logs.
